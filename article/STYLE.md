# 記事スタイルガイド

このサイトに記事を書く（または Claude に書かせる）ときの参考。
既存記事の文体・構成・トーンをサンプリングしてまとめたもので、ルールというより「揃えるべき空気」のメモ。

## 系統 1 : 技術記事（`com` / `phys` / `math` / `elec` …）

工作・自作 CPU・物理・数学などの記事はこちら。読者は同好の技術者を想定。

### 文体

- 「ですます調」が基本。
- 一文は短く。段落も短い。3〜4文で改行する。
- 段落冒頭の全角スペースは付けない。
- 句読点は **「、」「。」**
- 略語は初出で `CSR (Control & Status Registors)` のように英字フルを併記
- 数値・単位は半角＋スペース：`15 ns`、`5 V`、`240 mA`

### トーン

真面目一辺倒にしない。所々で力を抜く。実例：

- 「ロマンと実用性の両立！楽しい！感動できる！」
- 「来年の MFT2023 に出せたらいいな…？」
- 「†アジャイル開発†する」
- 「LLVM 神「力が…欲しいか…」」
- 「いっぱい売ってる！」
- 「サ終してて草」
- 「Docker すら動かすのが面倒な現代っ子なので」
- 「また、余談ですが、…暇があったら実装しようかな」

ふざけすぎず、強い断定もせず、開発の途中であることを隠さない。「未確認」「今後追加したい」「TODO」を堂々と残す。

### 構成テンプレ

```
（冒頭1〜3段落：いきさつ / モチベーション / その記事で何をするか）

## 目標 or 設計思想 or 概要
（箇条書きでも散文でも）

## 〜の仕組み / アーキテクチャ / 使い方
（節を ### で割って、表・コード・図を交互に挟む）

## 実装
（必要なら）

## 今後 / 課題 / 将来やりたいこと
（オープンエンドで締めて良い）
```

骨格は「**いきさつ → 目標 → 仕様/構造 → 実装 → 未解決の宿題**」。完璧にまとめようとせず、現在地のスナップショットを書く。

### 図・コード・表

- 図は `./img/foo.dio.svg` または `.png`。インラインで `![](./img/...)` 参照
- コードブロックは言語タグを付ける（` ```yaml ` ` ```bash ` 等）。出力例には空タグでも可
- 命令一覧・レジスタ一覧などはほぼ必ず Markdown 表で
- 数式は Typst 構文（`remark-math` + `rehype-typst`）。`$...$` / `$$...$$`

### 参考リンク

文中に普通に貼る。脚注より文中リンク派。

```
詳細はドキュメント：[Pandoc User's Guide 日本語版](https://...) を見てください。
```

## 系統 2 : 旅エッセイ・日記（`blog`）

旅行記・コミケ記・季節の記。読者は不特定多数の通りすがり。

### 文体

- **「である調」が基本**。短文を畳みかける
- 句読点は **「，」「．」**（全角カンマ・ピリオド）。系統 1 と明確に使い分け
- 体言止めを使ってよい
- 一段落＝一情景。情景の遷移で改段
- 五感・気象・時刻を頻繁に書く
- 史実・固有名詞・小ネタを織り込む（西行返しの松、重陽の節句、など）

### サンプル（`blog/2021-09-touhoku`）

> 八月の空気は焦燥感を掻き立てる．九月，途端に静まり返り，安寧を取り戻す．
> 静置された心の底の沈殿は，真に情熱を注ぐべきものへと駆動する．
>
> 少しの躁と，残り二日の青春切符を携えて，早朝の大塚駅に向う．

詩のリズムで散文を書く。比喩で殴る。説明しすぎない。

### 構成

`## YYYY-MM-DD 場所名` を冒頭に置き、その下は地名や情景のキーワードを `##` で並べる、あるいは時系列に沿って散文で繋ぐ。最後を体言止め一語で締めることもある（「帰路」など）。

## やらないこと

- `#` レベルの見出しを書く（`title` フロントマターと衝突）
- 機械的な「はじめに / おわりに」見出し（書かなくていい）
- 完了宣言・成果アピール調。途中でも投稿する
- 絵文字（フロントマター・本文とも）
- 過剰な強調 (`**太字**` の連打)。本当に強調したいキーワードだけに使う
- 句読点の混在。技術記事内で「，．」、エッセイ内で「、。」が混ざらないようにする
